# ECS Guide and Sandbox Scene Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Tick each box as it finishes and include the plan file in that task's commit.

**Goal:** Close issue #15 with three pieces: a runnable sandbox scene with wind built from scratch, an ECS usage guide in the repo for agents, and linked Obsidian notes that let the owner learn the ECS and program against it by hand.

**Architecture:** Wind is a small, engine-wide feature: one resource, one component and one physics system, running right after gravity with a default of zero. The sandbox scene in `src/app/` uses it, along with a scene-only respawn system that shows deferred commands. The repo guide and the Obsidian notes both teach from that real code.

**Tech Stack:** TypeScript, Vite, Vitest, ESLint (local rules: no comments, layers, filename-matches-export), Prettier (tabs, double quotes, no semicolons), Obsidian Markdown (wikilinks, Mermaid).

**Spec:** `superpowers/specs/2026-11-13-ecs-guide-design.md`

**Saved copy:** once this plan is approved, Task 0 copies it to `superpowers/plans/2026-11-13-ecs-guide.md`, as AGENTS.md rule 7 requires.

## Review Focus

1. **Several bodies crossing the edge in the same step.** Expected: every one is replaced and the number of bodies stays the same. Tested in Task 3.
2. **A body dragged off the left edge with the mouse.** There are no side walls, so without a check it would be lost forever. Expected: it is respawned like one that leaves on the right. Tested in Task 3.
3. **Wind on bodies that can't take force.** Static bodies, or anything with `WindExposure` but no `ForceAccumulator`, should be skipped quietly, with no error. Tested in Task 1.
4. **The default wind changes nothing in the demo and benchmark.** The existing app tests pass unchanged, and `installWorldResources` sets wind to `{0, 0}`. Tested in Task 2.
5. **An unknown or missing `?scene=` value.** Expected: the demo loads. Tested in Task 4 through `selectScene`.

- [x] **Step 1: Write the failing tests** in `tests/app/app.test.ts`, inside `describe("scenes")`.     - `world.store(Collider).size` is `SANDBOX_BODY_COUNT + 2`.
    - `world.resource(WindResource)` equals `SANDBOX_WIND`.
    - `world.resource(WorldSizeResource)` equals `{ width: SANDBOX_WIDTH, height: SANDBOX_HEIGHT }`.
  - `test("bodies past the right edge are replaced")`:
    - Take two exposed entities with `world.store(WindExposure).entityAt(0)` and `.entityAt(1)`.
    - Move both with `world.add(entity, Transform, { x: SANDBOX_WIDTH + SANDBOX_RESPAWN_MARGIN + 50, y: 300, angle: 0 })`.
    - Run one step.
    - Both old IDs are `isAlive === false`, and `WindExposure` size is still `SANDBOX_BODY_COUNT`.
    - The two new exposed entities (those not in the set of IDs taken before the step) have `x` between 0 and `SANDBOX_WIDTH / 4`.
  - `test("bodies past the left edge are replaced")`: the same, but with `x: -SANDBOX_RESPAWN_MARGIN - 50` for one entity.
  - `test("a replacement keeps the old body's exposure")`: give one body `exposure` 3.5 and move it past the right edge. After one step, exactly one exposed body has `exposure` 3.5.

- [x] **Step 3: Implement `buildSandboxScene`.**
  - Call `installWorldResources(world, SANDBOX_WIDTH, SANDBOX_HEIGHT)`, then set `WindResource` to a copy of `SANDBOX_WIND`.
  - Spawn a floor and a ceiling with `spawnStaticBody` and `createRectangleShape(SANDBOX_WIDTH, 50)`, just outside the top and bottom edges, as `wallPlacements` in `DemoScene.ts` does.
  - Spawn `SANDBOX_BODY_COUNT` mass-1 bodies with varied exposures (builder's choice, roughly 0.5–2) through a module-private `spawnSandboxBody(world, index, x, y, exposure): Entity`. An even `index` gives a circle and an odd one a box, which keeps the mix deterministic.
- [x] **Step 4: Implement `createSandboxRespawnSystem`.**

  - In `each`, when `x < -SANDBOX_RESPAWN_MARGIN` or `x > SANDBOX_WIDTH + SANDBOX_RESPAWN_MARGIN`, read the exposure *now*. Then call `world.defer((w) => { w.destroyEntity(entity); spawnSandboxBody(w, counter, x, y, exposure) })`.
  - The respawn point is in the left quarter. Stagger its `y` by the counter so bodies respawning in the same step don't overlap.
  - Never spawn or destroy directly inside `each`. That rule is the point of this example.
