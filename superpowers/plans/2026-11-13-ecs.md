# ECS Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Rebuild `engine-typescript/` on a sparse-set ECS with EnTT-style views. Port all of today's physics, rendering and input onto it, keep the demo behaving the same, empty the lint exceptions list, batch Canvas 2D drawing, and record benchmark numbers.

**Architecture:**
- **Core:** a generic `ecs` layer (`src/ecs/`) holds entities, sparse-set component stores with typed-array columns, views, the world, resources and a plain ordered `Schedule`.
- **Data and behaviour:** physics state lives in components (`src/components/`) and per-world resources (`src/resources/`). Behaviour lives in system factories that build their views once (`src/systems/`).
- **Geometry and collision:** pure functions in `shapes/` and `collisionDetectionSystem/`, plus an entity-based broad phase in `optimizations/broadPhase/`.
- **Rendering and app:** rendering systems batch draw calls in `src/rendering/`. Input bridging, scenes and schedule wiring live in `src/app/`.
- **Migration:** the old classes stay untouched until `main.ts` switches over (Task 16). They are deleted in Task 17.

**Tech Stack:** TypeScript 6 (strict), Vite 8, Vitest (new dev dependency), ESLint and Prettier with the repo's local lint rules, Canvas 2D.

**Spec:** `superpowers/specs/2026-11-13-ecs-design.md`. Read it alongside this plan; the plan argues from it.

**Where this plan is saved:** on approval, copy this file to `superpowers/plans/2026-11-13-ecs.md` (repo rule 6) and commit it on `feature/ecs` with `docs: add ecs implementation plan`.

## Review Focus

These are the inputs the spec implies but no feature test exercises. Each gets a test in the owning task.

1. **A view built before any entity has its component.** Expected: iterates zero entities, then sees entities added later. Stores must be created when the view is built, not lazily on first `add`. → Task 3 (`view sees components first added after the view was built`).
2. **A joint or a mouse drag whose entity was destroyed.** Expected: the joint is skipped and the drag ends, with no NaN and no crash. → Task 11 (`skips joint whose body was destroyed`), Task 14 (`releases drag when dragged entity is destroyed`).
3. **Bodies at negative coordinates,** for example after the window shrinks and bodies end up past the walls. Expected: the hash grid still pairs them. → Task 9 (`hash grid pairs bodies at negative coordinates`).
4. **Two circles with the same centre,** for example spawning twice on one spot. Expected: a finite normal (`(1, 0)`) instead of NaN poisoning the world. → Task 7 (`coincident circles give a finite normal`).
5. **Mouse pressed on empty space, then moved onto a body while held.** Expected: the body is picked when the cursor enters it, as today. → Task 14 (`picks body when held mouse moves onto it`).

### Task 2: Component definitions and the sparse-set `ComponentStore`

**Files:**
- Create: `src/ecs/defineComponent.ts`, `src/ecs/ComponentStore.ts`
- Test: `tests/ecs/ComponentStore.test.ts`

**Interfaces:**
- Consumes: `Entity`, `entityIndex` (Task 1).
- Produces, in `defineComponent.ts`:
  - `type NumericFieldType = "f64" | "f32" | "i32" | "u32" | "u8"`;
  - `type RefField<T>` (branded) and `ref<T>(): RefField<T>`;
  - `type Schema = Record<string, NumericFieldType | RefField<unknown>>`;
  - `interface ComponentDefinition<S extends Schema> { readonly id: number; readonly name: string; readonly schema: S }`;
  - `defineComponent<S extends Schema>(name: string, schema: S): ComponentDefinition<S>`. Ids come from a module counter: definitions are global constants, while data is per world.
  - `type Columns<S>` maps each numeric field to its typed array (`Float64Array`, `Float32Array`, `Int32Array`, `Uint32Array`, `Uint8Array`) and each `RefField<T>` to `(T | undefined)[]`;
  - `type FieldValues<S>` is the matching value types (`number` or `T`).

  This column mapping and the view tuple (Task 3) are the core's only non-trivial generics. The spec allowed one; the mapping is needed so that `columns.x[slot]` type-checks. Flag this in the PR.
- Produces `class ComponentStore<S extends Schema>`:
  - `constructor(definition: ComponentDefinition<S>, initialCapacity = 64)`;
  - `readonly definition`; `readonly columns: Columns<S>`. The object is stable, and its arrays are replaced on growth.
  - `get size(): number`; `entityAt(slot: number): Entity`;
  - `has(entity: Entity): boolean`, which also checks that `dense[slot] === entity`, so stale generations report false;
  - `slotOf(entity: Entity): number` (−1 if absent);
  - `add(entity: Entity, values?: Partial<FieldValues<S>>): number`, which returns the slot. Adding an entity that already has the component overwrites the given values and returns the existing slot. Unset numeric fields are 0, and unset refs are `undefined`.
  - `remove(entity: Entity): boolean`, a swap-remove that moves the last slot into the hole across every column and clears the vacated ref slot;
  - `clear(): void`.

### Task 5: Collider geometry functions

**Files:**
- Create: `src/shapes/colliderShapes.ts`, `src/shapes/colliderGeometry.ts`. They sit beside the old classes, which stay untouched.
- Modify: `src/shapes/README.md`
- Test: `tests/shapes/colliderShapes.test.ts`, `tests/shapes/colliderGeometry.test.ts`, `tests/shapes/README.md`

**Interfaces:**
- Produces, in `colliderShapes.ts`:
  - `const ColliderKind = { CIRCLE: 0, POLYGON: 1 } as const`; `type ColliderKindValue = 0 | 1`;
  - `interface ColliderShape { kind: ColliderKindValue; radius: number; localVertices: Float64Array; centroidX: number; centroidY: number }`;
  - `createCircleShape(radius: number): ColliderShape`, with empty `localVertices`;
  - `createRectangleShape(width: number, height: number): ColliderShape`, with local vertices TL, TR, BR, BL at ±w/2, ±h/2, the same order as `Rectangle.ts`;
  - `createPolygonShape(vertices: Vector2[]): ColliderShape`, where the centroid comes from `MathHelper.calcCentroid` and the local vertices are relative to it;
  - `circleInertia(mass, radius) = mass * r² * 0.5`;
  - `rectangleInertia(mass, w, h) = mass * (w² + h²) / 12`;
  - `polygonInertia(mass, localVertices)`: the `Polygon.calculateInertia` formula, with vertices already centroid-relative;
  - `shapeInertia(shape: ColliderShape, mass: number, rectangleSize?: { width: number; height: number }): number`.
- Produces, in `colliderGeometry.ts`. All functions take the collider columns and a slot, and write in place with no allocation:
  - `transformCollider(colliders: Columns<ColliderSchema>, slot: number, x: number, y: number, angle: number, angleChanged: boolean): void`. It writes `worldVertices` and AABB `minX/minY/maxX/maxY`. Circles get an AABB of centre ± radius. It recomputes `worldNormals` only when `angleChanged` or the normals are empty; each normal is the edge direction normalized, then `(dy, −dx)` (= `MathHelper.calcNormals`).
  - `translateCollider(colliders, slot, dx, dy): void` shifts the world vertices and AABB.
  - `isPointInsideCollider(colliders, slot, centerX, centerY, px, py): boolean`. Circles test squared distance against r². Polygons use the `Shape.isPointInside` half-plane test.
